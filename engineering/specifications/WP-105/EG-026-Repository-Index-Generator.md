# EG-026 — Repository Index Generator

## 1. Purpose

This specification governs the first built-in SIF Builder generator. The `repository.index` extension transforms the repository workspace into a deterministic Markdown artifact without performing direct file-system writes.

## 2. Public identity and artifact ownership

- Generator identifier: `repository.index`
- Artifact path: `engineering/INDEX.generated.md`
- Artifact type: `markdown`
- Generated marker: `<!-- Generated by SIF Builder: repository.index. Do not edit manually. -->`

These values are governed public behavior.

## 3. Components

```text
RepositoryIndexGenerator
RepositoryIndexViewFactory
RepositoryIndexView
RepositoryIndexSection
RepositoryIndexEntryView
RepositoryIndexMarkdownRenderer
```

The generator depends only on `BuilderContext` and the `RepositoryWorkspace` exposed by the Engine.

## 4. Input requirements

The generator requires a repository workspace containing a `RepositoryIndex`. Reference resolution is optional. Missing expected input is represented by diagnostic `GENERATOR-101`; it is not treated as an unexpected implementation exception.

## 5. Deterministic ordering

Sections use the following governed rank:

```text
ADR     10
RFC     20
SPEC    30
WP      40
GUIDE   50
REPORT  60
OTHER  900
```

Unknown types are ordered after governed types by case-insensitive natural comparison. Entries inside each section are ordered by normalized identifier and then normalized relative path.

## 6. Content

The generated document contains:

1. generated-file marker;
2. title and summary;
3. document counts by type and status;
4. resolved and unresolved reference totals when resolution exists;
5. document sections grouped by type;
6. identifier, title, status, version and repository-relative link;
7. unresolved-reference warning when applicable.

No timestamps, absolute paths, random values or environment-specific separators are emitted.

## 7. Path and Markdown safety

Source paths are normalized to `/`. Links are relative to the `engineering` artifact directory. Spaces and Markdown-sensitive URL characters are percent encoded. Table delimiters and line breaks in metadata are escaped. The generated artifact path remains protected by the Engine artifact model.

## 8. Composition

`DefaultCliApplicationFactory` registers `RepositoryIndexGenerator` explicitly in the default `GeneratorRegistry` and exposes its identifier through the component catalog. Runtime reflection and directory scanning remain prohibited.

## 9. Diagnostics

| Code | Severity | Meaning |
|---|---|---|
| `GENERATOR-101` | error | Required repository workspace or index is unavailable |

Unexpected failures continue through the existing `GENERATOR-500` handling in `GeneratorStage`.

## 10. Acceptance criteria

- the generator implements `GeneratorInterface`;
- exactly one artifact is returned for valid input;
- the artifact is deterministic and repository-relative;
- missing workspace data returns `GENERATOR-101`;
- Windows-style source paths are normalized;
- grouping and ordering do not depend on discovery order;
- the generator is visible through the CLI `list` command;
- PHPUnit, PHPStan level 8, Composer validation and `git diff --check` pass.
